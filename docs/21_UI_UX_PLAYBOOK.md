هذا المستند ليس بديلاً عن دستور الهوية البصرية. هو **طبقة التنفيذ** التي تحوّل مبادئ `docs/04_UI_UX.md` إلى قرارات قابلة للفحص والمراجعة.

## 0. المرجعية والحدود

**ترتيب المرجعية عند أي تعارض:**

1. `AGENTS.md` و`docs/` الوظيفية والعقود (API/الصلاحيات/البيانات).
2. `@khabir/ui-tokens` — المصدر الوحيد للألوان والمسافات والانحناء والظل والطباعة.
3. `docs/04_UI_UX.md` — الاتجاه البصري المعتمد.
4. هذا الدليل — كيف نُنفّذ ونراجع ونُثبت.
5. مهارات/مراجع التصميم (UI/UX Pro Max، Expo skills، MCPs) — **مصدر أفكار لا سلطة**؛ لا تتجاوز التوكنز أو العربية أولاً أو الأصول المحلية.

**حدود صلبة:**

- لا تغيير في العقود الوظيفية أو صلاحيات الخادم باسم التصميم.
- الخادم هو المُلزِم دائمًا؛ الواجهة طبقة عرض وتوجيه.
- لا بيانات أعمال مُختلقة في الواجهة أو العروض.
- لا `commit`/`push`/`deploy` ضمن مهام التصميم دون طلب صريح.

## 1. نموذج القرار: ثلاث كُلَف

كل تغيير واجهة يجب أن يخفض واحدة من هذه الكُلَف على الأقل، دون رفع الأخرى:

| الكلفة | السؤال | مثال قابل للقياس |
| --- | --- | --- |
| كلفة الفهم | هل يعرف المستخدم أين هو، وما المطلوب منه الآن؟ | عنوان شاشة صريح + CTA واحد أساسي |
| كلفة الوصول | كم خطوة/نقرة/حقلًا للمهمة؟ | منح اشتراك دون لصق UUID |
| كلفة الثقة | هل يعرف ماذا حدث بعد الإجراء، وماذا لو فشل؟ | نجاح يذكر الأثر + خطأ يذكر الفعل التالي |

**قاعدة التغيير:**

- لا تغيير بلا **فرضية** («تقليل خطوات الإشعار من 6 إلى 3») و**دليل قبل/بعد** (لقطة، عدد خطوات، فحص axe).
- كل تغيير يمس الواجهة يُغلق بلقطة AFTER + نتيجة فحص؛ ما لا يُقاس يُعتبر تجميلًا ويُرفض.
- التحسين الذي يزيد التعقيد بلا أثر قابل للقياس يُبسَّط أو يُلغى.

## 2. العربية وRTL (قواعد غير قابلة للتفاوض)

- الاتجاه الأساسي `RTL` في كل الشاشات. لا تُطبَّق RTL بقلب صورة الشاشة.
- الأيقونات الاتجاهية تُعكس (رجوع/التالي)؛ أيقونات المنصة الثابتة الدلالة لا تُعكس.
- **ممنوع `letter-spacing` على أي نص عربي** (لا في CSS ولا في `StyleSheet`).
- الأرقام غربية `latn` موحّدة في الجداول والعدادات والتواريخ.
- التواريخ تُنسَّق عربيًا عبر دالة مشتركة (`formatDateAr` في الأدمن) لا عبر `slice(0,10)` أو ISO خام.
- النصوص التشغيلية تبدأ بفعل: «أعد المحاولة»، «أكد التعيين»، لا «فشل العملية».
- لا مصطلحات داخلية في نصوص المستخدم (`request_status`، أسماء جداول، `UUID`، أكواد Prisma).
- العملة والتجميع الرقمي موحّدان، ولا تُعرض قيم وهمية (`0.00` أو UUID) كبديل عن الغياب؛ الغياب يُعرض «—» أو يُخفى الحقل.
- الجداول تستخدم أرقامًا جدولية (`tabular`) لثبات المحاذاة.

## 3. مصفوفة الحالات (إلزامية لكل شاشة وكل لوح)

لا تُعتبر الشاشة مكتملة حتى تُغطي حالاتها. الحالة الغائبة = عيب.

| الحالة | متى | ما يظهر | ممنوع |
| --- | --- | --- | --- |
| تحميل أولي | أول جلب للبيانات | سكيليتون بنفس هيئة المحتوى القادم + `aria-busy` | دوّامة تغطي الشاشة كلها |
| تحديث جزئي | إعادة جلب/تبديل صفحة | مؤشر داخل اللوح/الجدول، المحتوى السابق يبقى | مسح المحتوى وإظهار فراغ |
| فارغ — لا بيانات | لا سجلات أصلًا | سبب + إجراء بديل إن وُجد | «لا يوجد» فقط |
| فارغ — لا نتائج | تصفية/بحث بلا تطابق | ذكر أن السبب التصفية + زر «مسح التصفية» | خلطها بحالة «لا بيانات» |
| خطأ | فشل الشبكة/الخادم | رسالة عربية + سبب آمن + «إعادة المحاولة» | كشف أخطاء خام أو أسرار |
| نجاح | اكتمال إجراء | تأكيد غير معطِّل يذكر الأثر، ثم يحدّث الحالة | نافذة توقف كل شيء |
| صلاحية | دور لا يملك الإجراء | إخفاء، أو تعطيل مع سبب مكتوب | تعطيل صامت بلا تفسير |
| بيانات قديمة/جزئية | فشل تحديث مع وجود قديم | شريط «قد تكون البيانات غير محدّثة» + إعادة المحاولة | ادّعاء الحداثة |
| إرسال مزدوج | أثناء الطلب | `submitting` + تعطيل مؤقت + `aria-busy` | السماح بنقرتين |
| انقطاع شبكة (موبايل) | لا اتصال | حالة واضحة + إعادة محاولة عند العودة | فشل صامت |

**قاعدة النجاح:** التأكيد يصف **النتيجة** لا الزر: «تم تعيين الفني للطلب»، «تم إرسال الإشعار إلى المستخدم».

## 4. عقد المكوّنات (Vocabulary موحّد)

لكل مفهوم اسم واحد ومكوّن واحد لكل سطح. الموجود فعليًا:

| المفهوم | Admin (`apps/admin/src/components/ui.tsx`) | Mobile (`apps/mobile/src/ui`) | قواعد الاستخدام |
| --- | --- | --- | --- |
| زر أساسي | `SolidBtn` | `ActionButton` (variant أساسي) | CTA أساسي واحد لكل شاشة/لوح |
| زر ثانوي | `GhostBtn` | `ActionButton` (variant ثانوي) | لا يزيد عن إجراءين ثانويين متجاورين |
| زر خطر | `GhostBtn danger` | `ActionButton` (destructive) | لا يُنفَّذ مباشرة: حوار تأكيد + سبب عند الحذف |
| حقل نموذج | `formInput` + `<label>` | `FormField` | التسمية ظاهرة دائمًا؛ الخطأ أسفل الحقل؛ بلا placeholder كبديل عن التسمية |
| بحث | `search-field` (تصفية داخل الصفحة) | `SearchField` | لا فلتر غير مدعوم من الخادم |
| حالة | `StatusBadge` | `StatusBadge` / `StatusUnit` | اللون ليس وحده حاملًا للمعنى؛ النص حاضر |
| بطاقة/قسم | `Panel` + `SectionTitle` | `Card` / `SectionHeading` | عنوان صريح لكل قسم |
| حوار تأكيد | `ConfirmDialog` | `Alert.alert` أو حوار أصلي | للحالات غير القابلة للرجوع فقط؛ يذكر النتيجة |
| خطأ/فراغ | `ErrorState` / `EmptyState` | `ListError` / `ListEmpty` | نفس الدلالة على كل سطح |
| سكيليتون | `SkeletonRows` | `ListLoading` | يحاكي الهيئة النهائية |
| ترقيم | `Pagination` | قائمة لا نهائية/تحميل تدريجي | لا تُخفِ الإجمالي عند توفره |
| تنقل | تبويبات اللوحة | `AppHeader` + تبويبات الدور | عنصر نشط واضح + RTL صحيح |

**شروط أي مكوّن جديد:**

1. لا يوجد مكوّن قائم يفي بالغرض (يُذكر الدليل).
2. واجهة props صريحة (variants/haled states) بلا منطق أعمال داخلي.
3. كل القيم من `@khabir/ui-tokens`؛ لا hex/px عشوائية.
4. تغطية الحالات: افتراضي، تحميل، معطّل، خطأ، تركيز/ضغط.
5. وصولية: تسمية، دور، `aria-*`/`accessibilityLabel`، تركيز واضح، هدف لمس ≥44.
6. لا تكرار لمكوّن قائم باسم مختلف.

## 5. أنماط التفاعل

- **المهمة أولاً:** التبويبات/الأقسام تُرتَّب حسب سير العمل (مراجعة، تعيين، إشعار، تدقيق) لا حسب أسماء الجداول.
- **الكشف التدريجي:** التفاصيل عند الطلب (دُرج/شاشة تفاصيل)، لا حشو كل الأعمدة دفعة واحدة.
- **لا UUID في مسار المستخدم:** الاختيار بالبحث (اسم/جوال/بريد) والمعرّف يبقى للخادم. الحقول النصية للمعرّفات مسموحة فقط كمسار خبير موسوم صراحة «إدخال يدوي».
- **الجداول:** ≤5 أعمدة ظاهرة، معرّف بشري (اسم/رقم قصير)، إجراءات ≤2 + قائمة إضافية عند الحاجة، وتحويل إلى بطاقات عند العرض الضيق.
- **الحوار:** العنوان يسمّي الفعل، والنص يذكر النتيجة والحدود، وزر التأكيد يعيد الفعل («تأكيد الحذف») لا «موافق».
- **الصلاحيات:** الإخفاء للعناصر غير المتاحة، والتعطيل مع سبب حين يكون الإجراء جزءًا من فهم الشاشة. الخادم يبقى المُلزِم.
- **لوحة المفاتيح:** كل تفاعل قابل للوصول، والحوار يعيد التركيز إلى العنصر الفاتح عند الإغلاق، و`Esc` يلغي ما لم يكن مشغولًا.
- **الاستجابة:** لا تمرير أفقي مخفي؛ الأعمدة تتحول، والأزرار تلتف، والنص العربي لا يُقصّ بلا بديل.

## 6. الممنوعات التنفيذية (Hard rules)

1. قيمة لون/مسافة/انحناء/ظل خارج `@khabir/ui-tokens` (بلا استثناء موثّق).
2. `letter-spacing` على العربية.
3. إيموجي كأيقونة واجهة.
4. UUID أو معرّف قاعدة بيانات كنص أساسي للمستخدم.
5. `alert()` / `confirm()` في الويب، أو دوّامة تغطي الشاشة لتحديث جزئي.
6. إخفاء خطأ أو استبداله بـ«حدث خطأ» بلا فعل تالٍ.
7. تعطيل زر بلا سبب مرئي.
8. مكوّن مكرر جديد بلا مقارنة مع القائم.
9. مكتبة جديدة بلا بوابة القسم 7.
10. واجهات Web DOM أو API متصفح داخل الموبايل.
11. بيانات/إحصاءات مُختلقة لملء الواجهة.
12. الاعتماد على اللون وحده لحمل الحالة.
13. نصوص أساسية داخل صور (غير قابلة للترجمة/القارئ).
14. إرسال الإجراء مرتين بسبب غياب حالة `submitting`.

## 7. سياسة الاعتماديات

يُسمح بإضافة مكتبة فقط بعد اجتياز البوابة التالية، وتُوثَّق النتيجة في تقرير المرحلة:

1. **الدليل:** المكوّنات/الأدوات الحالية لا تحقق النتيجة (مع مثال ملموس).
2. **الحد الأدنى:** أصغر مكتبة/نطاق يحقق الغرض (لا framework كامل لأثر صغير).
3. **الأداء:** قياس الحزمة/الذاكرة/التشغيل قبل وبعد، ضمن ميزانية السطح.
4. **الترخيص والصيانة:** ترخيص متوافق + نشاط مشروع مقبول.
5. **مسار الإزالة:** كيف نتراجع عنها إن لم تثبت القيمة.
6. **القرار:** موافقة صريحة قبل الإدخال؛ لا تُضاف مكتبة «احتياطًا».

الحركة تُستخدم للمعنى (تأكيد انتقال/علاقة سببية)، لا للزينة؛ وتُحترم إعدادات تقليل الحركة.

## 8. ملاحظة أمان UX — P3-6 (تحليل فقط، بلا تنفيذ)

**الوضع الحالي:** جلسة الأدمن تُخزَّن في `localStorage` (`khabir.admin.session`: access + refresh + expiresAt + بيانات المدير).

**المخاطر:**

- أي XSS ناجح في أصل اللوحة يستطيع قراءة التوكنين واختطاف الجلسة.
- بقاء التوكن في التخزين الدائم يزيد نافذة الأثر بعد إغلاق التبويب.

**ما يخفف الخطر حاليًا:**

- access token قصير العمر مع refresh rotation أحادي الرحلة (طلب متزامن واحد).
- `tokenVersion` يبطل الجلسات عند تغيير أمني من الخادم.
- لا `dangerouslySetInnerHTML` في اللوحة (فحص سابق).

**الخيارات (قرار مستقل، خارج مراحل التصميم الحالية):**

| الخيار | الفكرة | الكلفة |
| --- | --- | --- |
| A | refresh في كوكي `httpOnly; Secure; SameSite` + access في الذاكرة | يحتاج CSRF strategy + تعديل خادم/عميل |
| B | إبقاء localStorage + تقوية CSP/Trusted Types وتقصير العمر | لا يزيل خطر XSS الأساسي |
| C | access في الذاكرة + refresh دوّار في كوكي | أفضل توازن أمني/تعقيد عند اعتماده |

**قواعد لا تتغير:** لا تُسجَّل التوكنات في logs، ولا تُعرض في رسائل خطأ، ولا تُمرَّر في URLs.

## 10. قائمة المراجعة (قبل الدمج/التسليم)

**قبل البدء**

- [ ] الغرض والمهمة والمستخدم محددون في سطر واحد.
- [ ] البيانات/الصلاحيات المطلوبة موجودة في الخادم (لا واجهة لبيانات غير متاحة).
- [ ] البديل القائم فُحص قبل إنشاء مكوّن جديد.

**المكوّن والحالات**

- [ ] كل الحالات في القسم 3 مغطاة (تحميل/فارغ/خطأ/نجاح/صلاحية/جزئي).
- [ ] لا حالة «لا يوجد» عامة بدل التمييز بين لا-بيانات ولا-نتائج.
- [ ] `submitting` يمنع الازدواج.
- [ ] الحوارات: عنوان فعل + نتيجة + إعادة تركيز + Esc.

**العربية/RTL**

- [ ] اتجاه صحيح، والأيقونات الاتجاهية معكوسة.
- [ ] لا `letter-spacing`، والأرقام latn، والتواريخ منسّقة.
- [ ] لا UUID/مصطلح داخلي في نص المستخدم.
- [ ] أسماء الحقول ظاهرة، والأخطاء أسفلها.

**الوصولية**

- [ ] تباين AA، وتركيز مرئي، وتنقل لوحة مفاتيح كامل.
- [ ] `aria-*`/`accessibilityLabel` للمكوّنات التفاعلية والأيقونات.
- [ ] أهداف اللمس ≥44 (موبايل)، ولا اعتماد على اللون وحده.
- [ ] axe = 0 مخالفات (ويب) أو مراجعة يدوية موثّقة.

**الأداء**

- [ ] لا صور/خطوط ثقيلة بلا حاجة، ولا مكتبة جديدة بلا بوابة القسم 7.
- [ ] ميزانية السطح: LCP < 2.5s وCLS < 0.1 للويب؛ الحركة لا تُسبب تقطيعًا على الأجهزة المستهدفة.

**الأدلة**

- [ ] لقطة BEFORE/AFTER (أو دليل حالة قبل/بعد).
- [ ] `typecheck` + `lint` + الاختبارات ذات الصلة.
- [ ] `git diff --check` نظيف؛ لا أسرار في الملفات.
- [ ] تحديث توثيق السلوك فقط إذا تغيّر فعليًا.

## 11. بروتوكول الأدلة والأوامر

**الويب (Admin / Landing):**

```powershell
pnpm --filter @khabir/admin typecheck
pnpm --filter @khabir/admin lint
$env:NEXT_PUBLIC_API_URL='http://localhost:3012'; pnpm --filter @khabir/admin build
pnpm --filter @khabir/landing typecheck
pnpm --filter @khabir/landing build
```

**الموبايل:**

```powershell
pnpm --filter @khabir/mobile typecheck
pnpm --filter @khabir/mobile lint
pnpm --filter @khabir/mobile test
pnpm --filter @khabir/mobile dev   # ثم تشغيل فعلي على محاكي/جهاز
```

**API عند لمس أي عقد:**

```powershell
pnpm --filter @khabir/api test
# مسار القاعدة الحقيقية على قاعدة جلسة معزولة فقط:
$env:KHABIR_TEST_SESSION_ID='<id>'; node apps/api/scripts/provision-session-db.mjs
$env:TEST_DATABASE_URL='postgresql://khabir_test:khabir_test_pw@localhost:<port>/khabir_test?schema=public'
pnpm --filter @khabir/api test:http-e2e
# ثم teardown-session-db.mjs
```

**الأدلة البصرية:**

- التسمية: `<surface>-<screen>-<state>-<YYYYMMDD>.png` وتُحفظ تحت `docs/assets/<surface>-audit/`.
- axe: حقن `axe.min.js` محليًا عبر Playwright ثم `axe.run(document)` بنطاق WCAG 2.2 A/AA.
- كل تقرير مرحلة يذكر: الأمر الحرفي، النتيجة الرقمية، اللقطات، والانحرافات المعروفة.
