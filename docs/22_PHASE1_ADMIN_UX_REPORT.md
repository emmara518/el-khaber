## 3. 1B — اختيار بشري بدل UUID + تأطير المتابعة

**المنطق المعتمد:** العميل يطلب، والفني يقبل ويتواصل؛ الإدارة تتابع. التدخل اليدوي (تغيير الحالة/الإسناد) **استثناء** لتصحيح الأخطاء.

- تبويب الطلبات: عمود «الإجراءات»، وكل صف يعرض «تدخل إداري استثنائي» مطويًا مع النص: «المسار الطبيعي: يقبل الفني الطلب من تطبيقه ويتواصل مع العميل…».
- الإسناد أُعيد تسميته «إسناد استثنائي»؛ البحث بالاسم/البريد/الجوال (أُضيف `displayName` لبحث الخادم)، والمعرّف اليدوي داخل «خيارات متقدمة».
- المنح: منتقي مستخدم بالبحث + خطة/ميزة بالاسم (`GET /admin/plans`, `/admin/entitlements` — super فقط). لا لصق UUID.
- الإشعارات: منتقي مستلم بالبحث؛ الإرسال معطّل حتى يكتمل المستلم/العنوان/المحتوى.
- **تحقق حي:** بحث `customer@qa` → نتيجة واحدة؛ الخطة ظهرت «بلاتينيوم · عميل · 99 EGP»؛ إشعار فعلي أُنشئ بـ`type=general` + audit؛ بحث فني بالاسم → نتيجة وإسناد جاهز؛ **لا UUID ظاهر** في نص الشاشات.
- axe: الطلبات 0/29، المنح 0/26، الإشعارات 0/25 (بعد إصلاح تكرار `id`).
- الأدلة: `docs/assets/admin-audit/phase1b/` (4 لقطات).

## 4. 1C — تفاصيل المستخدم والحالات والاستجابة

- **تفاصيل المستخدم (P3-9):** زر «تفاصيل» لكل صف مستخدم يفتح لوحًا عبر `GET /admin/users/:id`: البريد/الجوال/الدور/الحالة/التحقق، الاسم، ملف الفني (توثيق/تقييم/خبرة)، ملف التاجر، الاشتراك، عدد الطلبات/المنتجات، تاريخ الإنشاء وآخر دخول. حالات: تحميل/خطأ مع إعادة محاولة/تعليمات قبل الاختيار.
- **الحالات:** تعطيل مُفسَّر في المنح والإشعارات («اختر… أولًا»)، ودمج تاريخ موحّد `dd/MM/yyyy` بأرقام latn.
- **الاستجابة:** عند `≤860px` يتحول الجدول إلى بطاقات مع تسميات (`المعرف/المستخدم/الحالة والإجراءات`).
- **تحقق حي:** 20 صفًا يعرض «تفاصيل»؛ اللوح يحوي كل الحقول؛ عند 760px: `td display=block`، `thead display=none`، والتسمية تظهر «المعرف».
- axe: تفاصيل المستخدم 0/28، العرض الضيق 0/27، المنح 0/26 (بلا حالات غير حاسمة).
- الأدلة: `docs/assets/admin-audit/phase1c/` (3 لقطات).
