### Security changes verified in this candidate

- `AUTH-001`: email change requires the current password; reset issuance is
  refused while the new address is pending; the one-time verification token is
  hashed, address-bound, and consumed atomically.
- `AUTH-002/004/006`: separated lockout buckets, atomic reset claim, global
  logout revokes every refresh family.
- `SEC-001`: `anon`/`authenticated` grants revoked across the public schema.
- `PAY-001/002/007`: amount/currency snapshot at submission, DB-level
  idempotency for repeated references, proof cleanup and audit in the same
  transaction.
- `DB-002/003/004/006/008/009/011`: composite category FKs, prune/query
  indexes, money/coordinate range checks, status/timestamp invariant.
- `REL-003/004`: structured logger; long rate-limit identifiers are hashed
  deterministically instead of raising `23502`/overflow.
- `REL-001`: `/ready` verifies database reachability, unfinished migrations,
  and a critical table read; `/version` now exposes non-sensitive build
  identity for deployment verification.
