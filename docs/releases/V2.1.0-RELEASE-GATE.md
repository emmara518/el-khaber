## 5. Known limitations / deviations

1. **Schema drift baseline**: two PostGIS GIST indexes on `coordinates`
   cannot be expressed in Prisma 5; they are preserved in migrations and
   recorded in `apps/api/prisma/schema-drift-baseline.sql`. Any *other*
   drift fails CI.
2. **General HTTP throttle is per-instance in memory.** With N instances the
   effective request budget is N × configured. Auth throttling and login
   lockout are PostgreSQL-backed and shared. This is documented in
   `docs/security/rate-limiting.md` and startup logs.
3. **No visual UAT of the mobile offline/error states was performed on a
   device.** The states were typechecked, unit-tested, and the web export
   builds. The master task requires device screenshots; that remains open.
4. **Password reset UAT email** against a live provider was not executed
   (requires owner-provided provider credentials and approval).
5. **k6/Artillery load tests, multi-IP checks, and distributed rate-limit
   verification were not run.** No paid infrastructure was created.
6. **No production database, no Render deploy, no secret rotation, and no
   migrations were applied to khabir-dev/khabir-prod.** All external
   actions below still require owner approval.

### Incident disclosure (updated 2026-10-20)

Before the isolation guard (`eda245f`), the integration specs read
`apps/api/.env` and connected to **khabir-dev**. This happened in at least
**two full runs** (baseline `api-test-baseline.log` and S1 `api-test-s1.log`),
not once. The suites use deterministic `t10*-probe` markers and cleanup, but
cleanup did not cover audit logs.

A read-only check (`apps/api/scripts/check-dev-probe-residue.mjs`, guarded by
`ALLOW_DEV_READONLY_CHECK=true`) was run against the configured dev database.
No writes were performed. Results:

| Surface | Rows |
| --- | --- |
| probe users / admin users | 0 |
| service requests / locations / technicians | 0 |
| merchant profiles / products / reviews / messages | 0 |
| notifications / payment submissions / plans / entitlements | 0 |
| **audit logs** | **97** (`admin.manual_grant.entitlement`, marker `t10i-probe`) |

The 97 rows are audit entries for the subscription integration probe; the
probe users/grants themselves are gone. They contain QA probe identifiers,
not customer data. They were **not deleted**. The scoped predicate for an
owner-approved cleanup is:

```sql
DELETE FROM audit_logs
WHERE action = 'admin.manual_grant.entitlement'
  AND after_json::text LIKE '%t10i-probe%';
```

After `eda245f`, the resolver rejects Supabase/shared hosts before any write;
the check above only used a read-only connection explicitly allowed for this
incident.
