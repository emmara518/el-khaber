# Android release signing — EL-KHABIR (`@khabir/mobile`)

Package: `ai.khabir.app` · versionCode `1` · versionName `0.0.1`
(see `apps/mobile/android/app/build.gradle`).

## How release signing is wired

`android/app/build.gradle` → `signingConfigs.release` reads credentials
**only** from environment variables. A release build without all four
variables **fails fast** — it never silently falls back to debug signing:

| Variable                      | Meaning                                    |
| ----------------------------- | ------------------------------------------ |
| `MYAPP_UPLOAD_STORE_FILE`     | Keystore path (absolute, or relative to `android/app`) |
| `MYAPP_UPLOAD_STORE_PASSWORD` | Keystore password                          |
| `MYAPP_UPLOAD_KEY_ALIAS`      | Key alias                                  |
| `MYAPP_UPLOAD_KEY_PASSWORD`   | Key password                               |

```powershell
$env:MYAPP_UPLOAD_STORE_FILE = 'D:\path\to\upload.keystore'
$env:MYAPP_UPLOAD_STORE_PASSWORD = '<STORE_PASSWORD>'
$env:MYAPP_UPLOAD_KEY_ALIAS = '<KEY_ALIAS>'
$env:MYAPP_UPLOAD_KEY_PASSWORD = '<KEY_PASSWORD>'
$env:EXPO_PUBLIC_API_URL = 'http://10.0.2.2:3010/api/v1'  # QA API base
Set-Location apps/mobile/android
.\gradlew :app:assembleRelease   # APK (QA)
.\gradlew :app:bundleRelease     # AAB (QA / Play upload)
```

No keystore and no password is ever committed:
`apps/mobile/android/.gitignore` excludes `khabir-*-release.keystore`,
`release.keystore`, `upload-keystore*`, `*.jks` (and `android/` itself is
untracked — it is regenerated by `expo prebuild`).

## QA signing key (explicitly NOT the production upload key)

- File: `apps/mobile/android/app/khabir-qa-release.keystore` (local only,
  gitignored).
- Alias: `khabir-qa` · self-signed RSA-2048 · validity 3 years
  (2026-09-18 → 2029-09-17).
- Certificate DN contains `CN=EL-KHABIR QA ONLY NOT FOR PRODUCTION`, so any
  QA-signed artifact is identifiable as non-production.
- To mint a fresh QA key (use your own throwaway password, never reuse the
  production one):

```powershell
keytool -genkeypair -storetype JKS `
  -keystore apps/mobile/android/app/khabir-qa-release.keystore `
  -alias khabir-qa -keyalg RSA -keysize 2048 -validity 1095 `
  -storepass '<QA_STORE_PASSWORD>' -keypass '<QA_STORE_PASSWORD>' `
  -dname 'CN=EL-KHABIR QA ONLY NOT FOR PRODUCTION, OU=Mobile QA, O=Khabir, L=Cairo, ST=Cairo, C=EG'
```

## Remaining gap — EXACT production credential still needed

The **production upload key** does not exist in this repo (by design).
Before any Play release, an authorized owner must provide, out of band:

1. The production upload keystore file
   (recommended name `khabir-upload.keystore`, alias `khabir-upload`),
   **or** confirmation that Play App Signing is already provisioned and this
   is a new upload key to register in the Play Console.
2. Its four secrets, delivered as the four `MYAPP_UPLOAD_*` variables above
   (CI secret store / local env — never a file in git).

Until then, every `assembleRelease`/`bundleRelease` produced here is
**QA-signed** (see keystore DN) and must not be uploaded as production.

## Related build fix (bundling)

Release bundling on Windows monorepos previously failed in
`:app:createBundleReleaseJsAndAssets` (Metro could not resolve the
pnpm-symlinked `expo-router/entry` when the Gradle plugin passed
`--entry-file` relative to the JS root). Fixed by
`apps/mobile/scripts/expo-export-embed-cli.js` (backport of upstream
expo/expo#40563), wired via `react { cliFile = ... }` in
`android/app/build.gradle`. Debug builds were never affected (bundling is
skipped for debuggable variants).
