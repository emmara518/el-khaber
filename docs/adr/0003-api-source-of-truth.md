# ADR-0003: API Source of Truth

- **Status:** Accepted
- **Date:** 2026-09-02
- **Deciders:** CTO / Technical Lead

## Context

Multiple artifacts describe the API: the constitution (`docs/07_API.md`), the NestJS implementation, the OpenAPI export, and the generated client types. Without an explicit ordering, drift and "second source of truth" failures occur — the OpenAPI schema is treated as authoritative and quietly diverges from the implementation, or clients hand-type DTOs that drift from the server.

The CTO directed: Constitution/API specification → NestJS implementation → OpenAPI export → generated client types. OpenAPI must **not** become an independent business-rule authority.

## Decision

The order of authority is:

```
1. docs/07_API.md              (constitution — human source of truth)
2. NestJS implementation        (code — primary execution authority)
3. OpenAPI export               (derived artifact — never hand-edited)
4. Generated client types       (derived artifact — never hand-edited)
```

### Rules

- `docs/07_API.md` is the human-readable specification. When behavior changes, this file is updated **before or alongside** the NestJS change, never after.
- The NestJS implementation is the primary execution authority. OpenAPI and types are produced **from** the implementation, not the other way around.
- The OpenAPI export is generated by NestJS tooling (e.g. `@nestjs/swagger`) and committed to `docs/api/openapi.yaml` as a build artifact, not as a hand-edited spec.
- `packages/shared-types` is generated from the OpenAPI export via `scripts/gen-types.ts`. Hand-written types are forbidden for any DTO that already exists in `docs/07_API.md`.
- If a client needs a type before the OpenAPI export is updated, the client waits for the export. No parallel type definitions.
- The OpenAPI file is regenerated in CI and any drift produces a failing check.

### Forbidden

- Hand-editing `docs/api/openapi.yaml`.
- Hand-typing DTOs in `apps/mobile`, `apps/admin`, or `apps/landing` for entities that exist in `docs/07_API.md`.
- Treating OpenAPI as a business-rule authority. It is a *shape* contract only; business rules live in code and in the constitution.
- Accepting an API change in the constitution without also implementing it (`10` §20).

## Rationale

- Constitution first keeps the documentation honest; if a developer disagrees with an API decision, the disagreement is resolved in the constitution, not in a fork of the schema.
- NestJS as the execution authority means tests, runtime behavior, and types all agree.
- Generated types only prevent the most common client/server drift bugs.
- The OpenAPI export exists for tooling (codegen, docs viewers) and is never the canonical spec.

## Consequences

- The OpenAPI export must be reproducible from the running NestJS process or its build output.
- Type generation runs in CI; drift fails the build.
- A new endpoint requires (in this order): constitution update → implementation → regenerated OpenAPI → regenerated client types → client integration.
